# 01. 제품 범위와 결정 사항

## 1. 목적과 사용 시나리오

최종 비전은 음원 → 악기별 분리 → 악기별 채보 → 악보 제공이다. 이번 개발 단위는 첫 번째 화살표까지만 완성한다. 분리 결과를 후속 채보가 그대로 읽도록 시간축, 악기 라벨, 모델 이력은 처음부터 보존한다.

사용자는 파일을 선택하고 분리 설정을 고른다. 실행 전 예상 저장 공간과 모델 다운로드 여부를 확인한다. 완료 후 원본·각 파트를 같은 위치에서 들어보고 Solo/Mute, 구간 반복, 볼륨 조절로 결과를 확인한다. 선택한 stem 또는 전체 결과를 내보낸다. 재실행은 이전 결과를 덮어쓰지 않는 별도 작업이다.

분리란 원래 녹음 트랙을 정확히 복원하는 작업이 아니라 혼합 음원에서 각 음원을 추정하는 작업이다. 같은 기타 두 대, 패드와 스트링, 리버브, 이미 잘린 대역은 완벽하게 복원된다고 약속하지 않는다. ‘피아노 파일 생성 성공’과 ‘피아노 소리가 정확히 분리됨’은 별도 결과다.

## 2. 단계별 제품 범위

| 단계 | 제공하는 것 | 제공하지 않는 것 |
|---|---|---|
| P1 기준 동작 | vocals / drums / bass / other의 4-stem CLI, 파일·manifest | UI, 세부 악기 품질 약속 |
| P2 목표 분리 | vocals / drums / bass / guitar / piano / other의 6-stem 후보 비교 | 기타·피아노가 항상 깨끗하다는 보장 |
| P3 로컬 사용 도구 | 파일 선택, 작업 상태, 동기 재생, Solo/Mute, 반복, WAV export | 외부 공개 서버, 계정, 결제 |
| P4 확장 실험 | 선택 악기 전문 모델, 드럼 세부 분리, 다악기 탐색 | 53개 모두를 독립적 원본 트랙으로 복원 |
| 같은 제품의 후속 Phase B–F | MIDI, MusicXML, TAB, PDF, 곡 분석 | 이번 분리 개발의 완료 조건에 포함하지 않음 |

4-stem은 엔진 검증용 중간 단계다. 사용자의 악기별 분리 목표를 4개로 영구 축소하지 않는다. 6-stem에서 기타·피아노 기준을 충족하지 못하면 ‘실험적’으로 남기고 전문 모델 비교를 계속한다.

## 3. 초기 입력·출력 제안

| 항목 | 로컬 v0.1 계약 |
|---|---|
| 입력 | WAV, FLAC, MP3 파일 하나 |
| 길이 | 1초 이상 15분 이하; 제한은 설정으로 관리 |
| 크기 | 최대 1 GiB; 압축 파일은 디코딩 후 크기도 제한 |
| 채널 | mono 또는 stereo; 다채널은 자동 downmix하지 않고 설명과 함께 거절 |
| sample rate | 8–192 kHz 디코딩 허용; 낮은 음질은 경고하며 모델 입력은 별도 resample |
| 기준 시간축 | 44,100 Hz, stereo, float32 PCM, 시작 0, 고정 frame 수 |
| 원본 | 바이트 단위 원본 보존 + SHA-256; 압축 원본의 디코딩 이력 기록 |
| 분석 출력 | 기준 시간축의 float32 WAV; 원본 손상 방지용 원시 추정값 보존 |
| 사용자 export | 공통 gain을 적용한 PCM24 WAV + manifest; ZIP은 선택 |
| 재생 | 최대 6개 stem 및 원본 비교; 53개 전체 동시 재생 제외 |

기준 형식은 모델을 고정한다는 뜻이 아니다. 모델별 입력 rate가 다르면 adapter가 왕복 변환한다. 결과의 시간 0은 디코딩된 기준 음원의 시작이며, MP3의 컨테이너 시간이나 YouTube 영상의 시각과 동일하다고 가정하지 않는다.

## 4. 설계 결정

| ID | 결정 | 이유 / 재검토 조건 |
|---|---|---|
| D01 | 로컬 CLI 우선, 이후 localhost UI | 모델 품질과 서비스 운영 문제를 분리해 검증 |
| D02 | 전용 separation 모듈로 설계 | 오디오 처리·모델 실행·사용자 화면의 책임 분리 |
| D03 | 기준 모델 → 후보 비교 → 채택 | ‘최신’ 또는 지원 악기 수로 품질을 추정하지 않음 |
| D04 | 모델 학습, 자동 앙상블은 보류 | 비교 근거 없이 비용과 변수를 늘리지 않음 |
| D05 | 악기 탐지로 초기 출력 생략하지 않음 | 조용한 악기와 짧은 솔로의 누락 방지 |
| D06 | BPM·키·코드 분석은 분리 선행 조건 아님 | 분리 자체 검증에 필요하지 않음 |
| D07 | 임의의 정확도 백분율 표시 금지 | 출력 에너지는 악기 존재 확률이나 순도와 다름 |
| D08 | 원본과 추정 stem의 gain 관계 유지 | 청취 비교 및 채보 입력 왜곡 방지 |
| D09 | YouTube URL 입력은 후속 검토 | 이번 파일 기반 엔진의 독립성을 유지 |
| D10 | 외부 전송 기본 없음 | 로컬 파일 처리; 모델 다운로드는 네트워크 사용으로 구분 |

## 5. 화면 동작 요구사항

- 실행 전: 원본 길이·채널·형식, preset, 모델 준비 상태, 결과 경로 표시.
- 처리 중: 현재 단계, 실제 완료 chunk 수, 경과 시간, 취소 버튼. 최초 ETA는 미정으로 표시하고 근거가 생길 때만 추정한다.
- 처리 후: 원본 / 6개 목표 파트, 모델 이름, 경고, 선택·전체 export.
- 원본 비교 모드와 stem 믹스 모드는 독립 선택한다. 원본과 전체 stem을 기본적으로 동시에 틀지 않는다.
- 여러 Solo는 합집합이며, Solo가 하나라도 켜져 있으면 Solo된 트랙 중 Mute되지 않은 것만 재생한다.
- 볼륨은 청취 설정이다. 원시 결과 파일을 변경하지 않는다. export에 적용할 경우 별도 선택과 gain 기록이 필요하다.
- 실패한 작업의 임시 파일은 완성된 결과처럼 표시하지 않는다. 취소·재시도·이전 성공 결과로 돌아갈 수 있어야 한다.

## 6. 향후 악보 연결 계약

채보 모듈에는 `asset_id`, `stem_id`, 악기 family, rate, frame 수, 시간 0 기준, source hash, 모델 provenance, 경고를 전달한다. BPM이나 confidence를 모르면 null로 둔다. 향후 정제 오디오가 추가되어도 원시 stem을 교체하지 않고 파생 asset과 parent 관계를 추가한다.

리듬 기타/리드 기타는 악기 종류와 다른 연주 역할이다. 모델이 guitar만 반환했으면 electric/rhythm 등의 라벨을 추측해서 붙이지 않는다. 이번에는 family 수준 라벨부터 제공한다.
