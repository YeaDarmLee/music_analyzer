# 악기별 음원 분리 — 개발 전 설계 패키지

작성: 2026-10-05 · 상태: v0.5 · S1–S2 검증 완료 · S3 기능 구현·실제 곡 1개 검증

## 이번에 만드는 것

사용자의 PC에서 음원 파일을 읽어 악기별 오디오로 분리하고, 같은 구간을 원본과 비교해 들으며, 후속 악보 생성에 사용할 원본 품질의 stem과 처리 이력을 저장한다. 이번 범위에는 MIDI·악보 생성, 모델 학습, 클라우드 서비스 구현이 없다.

사용자가 확인한 방향은 **문서부터 작성하고, 악기별 분리를 먼저 개발하며, 내 PC에서 실행한다**는 것이다. 나머지 제품 한계값과 합격 기준은 본 문서의 설계 제안이며 실측 결과가 아니다.

## 읽는 순서

1. [제품 범위와 결정 사항](01_SCOPE_AND_DECISIONS_KO.md): 무엇을 만들고 어디까지 보장하는가.
2. [구현 설계](02_IMPLEMENTATION_DESIGN_KO.md): 데이터, 오디오 처리, 모델 연결, 작업 복구, 청취 화면.
3. [개발 단계와 검증 계획](03_DELIVERY_AND_VALIDATION_KO.md): 작업 순서, 산출물, 단계별 통과 조건.
4. [모델 근거와 미결 사항](04_MODEL_EVIDENCE_KO.md): 출처, 라이선스 검토, 실행 환경과 결정 기록.

## 첫 개발 작업

문서 검토 후 **환경 검증 → 오디오 입출력 계약 → 기준 모델 한 개 → 품질 측정** 순서로 진행한다. 첫 구현 산출물은 ‘파일 한 곡을 입력하면 동일 타임라인의 stem 파일들과 manifest가 저장되는 로컬 CLI’다. GUI와 세부 악기 분리는 그 다음이다.

현재 PC에서 `nvidia-smi`로 RTX 3060 / VRAM 12 GiB / 드라이버 560.94를 확인했다. PyTorch/CUDA 실행, 실제 모델 추론 및 저장 무결성은 S1에서 측정하며 결과를 보고서에 기록한다. 53-stem 실행 가능성과 처리 시간도 미확정이다.

## 완료의 의미

설계 문서 작성과 모델 품질 입증은 다르다. 문서에서는 인터페이스·실패 처리·검증 절차를 구체화한다. 실제 분리 품질·VRAM·속도·적정 chunk 길이·최종 checkpoint는 실험 단계에서 확정한다. 확인되지 않은 수치를 성능 보장으로 사용하지 않는다.

music_analyzer는 빈 폴더에서 시작하는 독립 프로젝트다. 설계 문서와 전체 곡 분리 CLI를 구성하며 사용자 UI는 후속 단계에서 구현한다.
