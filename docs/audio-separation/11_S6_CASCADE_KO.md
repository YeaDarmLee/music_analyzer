# S6 확정 보컬과 반주 악기 분리 연결

2026-10-05. 사용자 청취 결과에 따라 **Mel-Band RoFormer를 보컬 단계로 확정**했다. 사용자는 약간 더 다듬을 여지가 있지만 기존보다 본인 기준으로 약 80% 더 정확하다고 평가했다. 이는 주관적 비교 의견이며 객관적 정확도 80%라는 의미가 아니다.

실행 흐름은 원본 → RoFormer 보컬 추정 → 원본 minus 보컬인 전체 반주 → 반주에서 악기 분리로 정했다. 보컬 제거는 한 번만 수행한다.

## 현재 구현

`separate-pipeline` 명령은 두 작업을 순서대로 실행한다. 기존 RoFormer 작업을 재사용할 수도 있다. 중간 반주는 FLOAT WAV로 입력 등록하며, 샘플을 블록 단위로 비교해 **샘플 값과 프레임 수의 완전 일치**를 검사한다. WAV 헤더와 파일 해시는 재포장 때문에 달라질 수 있어 각각 별도로 기록한다.

악기 단계는 우선 기존 `quality_6s` 모델을 연결했다. 최종 6개 트랙의 참조는:
- vocals: 첫 번째 RoFormer 작업
- drums, bass, guitar, piano, other: 반주를 입력으로 받은 두 번째 작업

두 번째 모델이 출력한 vocals는 진단용 보컬 잔여물로 그 작업에 보관하며 최종 보컬과 교체하거나 더하지 않는다. 이에 따라 최종 여섯 트랙 합이 원본을 정확히 재구성한다고 보장하지 않는다. pipeline manifest에는 원본, 중간 입력, 두 작업 ID, 결과 경로, 해시 및 단계별 상태를 기록한다. 파일은 복제하지 않고 기존 raw 결과를 참조한다. 반주 단계 실패 시 완료된 보컬 작업은 보존한다. pipeline 전체의 중단·복구는 자동 재개하지 않으며, 보컬 작업 ID로 악기 단계부터 다시 실행할 수 있다.

## 실행

프로젝트 루트 PowerShell:
```powershell
.\.venv\Scripts\python.exe -m music_analyzer.cli separate-pipeline --input "millsage - 기사개전 (起死開戦).mp3"
# 보컬 결과 재사용
.\.venv\Scripts\python.exe -m music_analyzer.cli separate-pipeline --vocal-job-id job_a5b0e6a61f45478c902b72754700dba7
```

`scripts/separate.ps1`의 기본 실행도 이 파이프라인을 사용한다. 기존 단일 모델 실행은 명시적인 Preset 선택으로 유지한다.

## 채택 범위

보컬 모델 선택은 확정했다. 반주에 적용한 기존 6트랙 모델은 연결 검증용이며 악기 품질은 아직 채택하지 않았다. 보컬 단계에서 소실된 연주가 후속 악기 단계에서 되살아난다고 가정하지 않는다. 후속 개선은 같은 반주 입력으로 전문 악기 모델을 비교하고, 원본 직접 분리와 함께 들어 손상 누적 여부를 확인하는 순서다.

## 실제 연결 검증

기사개전의 확정 보컬 작업을 재사용해 전체 반주 악기 분리를 완료했다. pipeline_5ed2f61a401a4c10a0825d4feacab7ca는 SUCCEEDED이며 중간 샘플 보존, 최종 6개 트랙 참조 및 파일 해시를 검증했다. 실패한 보컬/다른 보컬 모델을 후속 단계에 넘기지 않는 테스트 2개 통과. 기존 회귀 테스트는 직전 단계에서 112개 통과했다.
