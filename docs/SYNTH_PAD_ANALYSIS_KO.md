# 신디 패드 분류 문제 분석 보고서

작성 기준: v15 (`b871de2`). 수치는 `docs/` 결과 JSON과 `data/ground-truth/cases/*-v15/report.json`에서 가져왔다. SDR은 정답과의 오차 기준이며 높을수록 좋다. "정답 신호 비율"은 트랙에 잡힌 정답 신호의 크기 비율이다.

## 1. 한 줄 결론
신디 패드는 **스트링으로 분류되고, 분류 근거가 되는 모델 어디에도 신디로 나오지 않는다.** 현재 가진 모델·후처리로는 해결되지 않으며, **정답이 있는 패드 샘플이 사실상 1개**라서 새 방법을 검증할 수 있는 데이터도 부족하다.

## 2. 지금까지 추출·검증한 범위
| 구분 | 내용 |
| --- | --- |
| 정답 있는 패드 샘플 | Slakh Track00020의 `Pad 1 (new age)` 1개. 음량만 달리한 변형 3개(일반·작은·패드 없음)이며 서로 다른 패드는 1개뿐이다. |
| 정답 있는 다른 신디 | 없음. 신디 정답이 있는 조건은 위 3개가 전부다. |
| 스트링 정답 | 실제 녹음 바이올린, Slakh 스트링(String Ensemble 등), 보컬+바이올린 합성 등 13개 조건. 패드와의 혼동을 볼 수 있는 조건은 위 패드 3개뿐이다. |
| 실제 곡 | 완료된 분석 38건에 신디 트랙이 있다. 정답이 없어 정확도는 판정할 수 없고 에너지 수준만 볼 수 있다. |
| 시험한 모델 헤드 | mega7 7개 + mega53 원본 53개 중 신디·건반·오르간·스트링·바이올린·비올라·첼로 등 관련 헤드 전부. |

## 3. 패드 신호가 어디로 가는가 (정답 대비 비율)
Slakh 패드 조건, 15초 구간.

| 단계 | 신디 | 스트링 | 비고 |
| --- | ---: | ---: | --- |
| 원곡 문맥 모델(mega7) | 0.0% | 81.8% | 처음부터 스트링으로 인식 |
| 잔여 반주 재분리(mega5) | 0.0% | 88.7% | 같은 결과 |
| 최종 v15 출력 | **0.3%** | **88.7%** (추가 반주 10.7%) | 신디 SDR 0.00dB (작은 패드 -4.03dB) |

- 최종 출력에서 패드 정답과 스트링 정답이 모두 같은 스트링 트랙으로 들어간다. 스트링 SDR은 패드가 섞이면서 13.63 → 0.00dB로 무너진다(패드 없는 조건은 13.63dB).
- 작은 패드는 신디 트랙에 1.1%만 잡히고 스트링 SDR은 13.13dB로 유지된다. 소리가 작아 스트링 품질에 영향을 덜 준다.

## 4. 모델 헤드별 응답 (패드 정답 대비)
| 헤드 | 일반 패드 | 작은 패드 |
| --- | ---: | ---: |
| bowed_strings | 78.5~82% | 49.6~82% |
| strings | 91.2~95% | 56.6~90% |
| violin | 66% | 59% |
| viola | 7% | 26% |
| **synth** | **0%** | **0%** |
| keys | 4.7% | 21.6% |
| organ | 0% | 0% |

신디 전용 헤드는 패드에 반응하지 않고 이 곡의 일렉기타에 반응한다(16~36%). 건반(keys) 헤드만 패드에 약하게 반응하며, 작은 패드에서 21.6%까지 올라가지만 피아노(94%)에 더 강하게 반응해 구분 근거로 쓰기 어렵다. 즉 모델이 "신디"를 패드가 아니라 건반·리드류로 학습했을 가능성이 크다(추정이며 학습 데이터 정보는 없다).

## 5. 시도했고 채택하지 않은 방법
| 방법 | 패드 결과 | 부작용 | 판단 |
| --- | --- | --- | --- |
| CLAP 문장 질의로 신디 교체 | 일반 SDR 0.01 → 2.06dB | 작은 패드 -4.01 → -16.53dB, 패드 없는 스트링 13.65 → 5.42dB | 제외 |
| 잔여 반주에서 스트링 신호 추가 | 스트링 0.52 → 0.39dB | 개선 없음 | 제외 |
| 문맥 근거로 스트링 복귀(v13) | 패드 영향 거의 없음(스트링 0.52 → 0.00dB로 소폭 하락) | 바이올린은 크게 개선 | 채택, 패드 미해결 |
| 신디/스트링/브라스 강제 재분류 | 정답 오차 증가 | 다른 악기 손상 | 제외 |
| 원곡 전체를 한 번에 재분리 | 조용한 신디 정확도 하락 | 일부 스트링 정확도 하락 | 제외 |

## 6. 실제 곡의 신디 트랙 수준 (참고)
완료된 38건의 신디 트랙 에너지는 원곡 대비 -13.8 ~ -78dB로 곡마다 크게 다르다. 최신 버전(v12~v15) 곡에서도 -16dB(`R`)부터 -78.5dB(sumika 픽션)까지 흩어져 있다. 정답이 없어 이 값이 맞는지 판단할 수 없다. 패드가 스트링에 섞여 신디가 비어 있을 가능성은 있으나 실제 곡에서 확인한 것은 아니다.

## 7. 왜 지금 해결되지 않는가
1. **모델 한계:** 패드와 스트링을 구분하도록 학습된 헤드가 없다. 두 소리는 지속음·넓은 주파수 대역이 비슷해 후처리로 구분할 단서(위상·배음 구조)가 약하다.
2. **데이터 한계:** 서로 다른 패드가 1개뿐이라 어떤 개선도 일반화 여부를 알 수 없다. 이 1개에 맞추면 과적합이 된다.
3. **평가 한계:** 실제 곡의 패드 정답이 없다.

## 8. 선택지
| 선택지 | 필요한 것 | 기대 | 위험 |
| --- | --- | --- | --- |
| A. 패드 데이터 확보 후 미세조정 | Slakh2100 전체(수십 GB) 또는 MIDI+사운드폰트 합성으로 다양한 패드/스트링 쌍 | 신디 헤드가 패드를 인식 | 학습 시간·VRAM(RTX 3060 12GB), 모델 라이선스 검토(현재 상업 사용 `REVIEW_REQUIRED`) |
| B. 데이터만 먼저 만들고 평가 세트 확대 | 패드 10종 이상 합성 | 지금 방법들의 한계를 정확히 측정 | 해결은 아님 |
| C. 패드 없이 현상 유지 | 없음 | 비용 0 | 패드가 스트링으로 계속 들어감 |
| D. 사용자에게 이동 수단 제공 | 트랙 간 이동 UI | 사용자가 직접 재분류 | 자동 정확도는 그대로 |

**권장:** B로 평가 세트를 먼저 넓혀 현재 방법의 실제 성능을 확인한 뒤, 결과가 나쁘면 A로 간다. 지금 데이터(패드 1개)로 A를 시작하면 학습 결과를 검증할 수 없다.

## 9. 확인하지 못한 것
- 실제 곡에서 패드가 스트링으로 들어가는 비율.
- 합성 패드가 아닌 실제 녹음 패드에서의 응답.
- 사용 중인 모델의 학습 데이터 구성(공개 정보 없음).
