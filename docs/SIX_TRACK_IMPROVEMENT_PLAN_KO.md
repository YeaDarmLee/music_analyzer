## 0. 목적과 불변 원칙

**목적**: 실제 곡에서 6개 stem이 모두 사용자 청취 기준 90점 안팎이 되게 한다. 특히 드럼(현재 0점)을 쓸 수 있는 수준으로 올린다.

**불변 원칙 (이 계획의 모든 단계에 적용)**
1. **무료이고 상업 사용이 가능한 오픈소스·라이브러리만 production에 쓴다.** 코드, 사전학습 가중치, 학습 데이터를 각각 따로 본다. 저장소가 MIT라는 사실은 가중치나 학습 데이터의 허락이 아니다.
2. **증거가 없으면 제외한다.** 가중치 라이선스, 학습 데이터, 출처 URL 중 하나라도 확인되지 않으면 production 후보가 아니다. "확인 못 함"은 허용이 아니다.
3. production 경로에는 출처 불명(UNKNOWN) 가중치와 비상업·학술 전용 데이터로 학습된 가중치를 넣지 않는다.
4. 합 보존을 유지한다. 최종 `other = 반주 − (드럼 + 베이스 + 피아노 + 기타)`.
5. 단계마다 **통과 기준과 중단 기준**을 미리 정하고, 결과가 나쁘면 억지로 채택하지 않는다.
6. 새로운 별도 연구 루프를 열지 않는다. 이 계획의 단계를 벗어나는 실험은 사용자 승인 후에만 한다.

## 1. 현재 상태

### 1.1 현재 구성

|---|---|---|
| 보컬/반주 분리 | Mel-Band RoFormer (KJ) | 가중치 라이선스는 게시자(README) MIT 선언뿐, 학습 데이터 미확인 |
| 악기 4종 분리 | Mega53에서 헤드 4개만 뽑은 `core4` (피아노·기타·베이스·드럼) | 공식 Mega53 출력과 비트 동일. 근거는 저장소 이슈 #245의 저자 MIT 선언 한 건, 학습 데이터 미확인 |
| 나머지 | 후처리 없음 | `other`는 반주에서 4개를 뺀 나머지 |

### 1.2 사용자 청취 점수와 진단
| stem | 점수 | 측정으로 확인한 사실 |
|---|---|---|
| 보컬 | 90+ | KJ 출력은 충분하다 |
| 피아노 | 70 | `core4`가 `basic_6`(개발용) 대비 −1.1 dB, 심벌 대역 −6 dB |
| 기타 | 70 | 약 −1.3 dB |
| 베이스 | 80~90 | 거의 동일 |
| 드럼 | 0 | 실제 6곡에서 원곡 대비 −5 dB → −17 ~ −32 dB. `basic_6` 드럼 에너지의 71~98%가 `other`로 이동. `commercial_13`의 percussion 경로도 회복시키지 못함(최대 1.8%) |

- 손실은 `core4` 단계에서 이미 생기고 후처리가 더하는 손실은 0.6 dB 이하다.
- 합성 평가(드럼 −2.2 dB)가 실제곡 실패(−11 ~ −28 dB)를 전혀 보여주지 못했다. **평가 방식 자체를 바꿔야 한다.**
- 이미 해 보고 기각된 것: 추론 파라미터 조정(효과 작고 비용 2.3배), Mega53 보조 헤드(악화), Wiener 정제(크게 악화).
- 6곡이 모두 큰 소리로 마스터링된 팝·록이라 어떤 조건에서 실패하는지는 아직 분리하지 못했다.

## 2. 외부 보고서 검토

### 2.1 받아들이는 것
- **"core4 후처리를 더 만지기 전에 다른 모델을 같은 입력에 넣어 본다"** 는 방향에 동의한다. 드럼 에너지 대부분이 `other`에 있으므로 신호처리로 되돌리는 것보다 좋은 분리기를 쓰는 편이 정보량이 크다. 이전에 내가 첫 순서로 제안한 "DSP로 `other`에서 드럼 회수(B안)"는 후순위로 내린다.
- 실제 곡 평가와 정답이 있는 평가를 **분리**한다.
- 평균이 아니라 하위 10%와 최악 사례를 기록한다(95, 95, 95, 95, 20보다 90, 91, 89, 92, 88이 낫다).
- `drum-in-other leakage` 지표를 별도로 둔다. 드럼이 약한 것, `other`로 간 것, 깨진 것을 구분하기 위해서다.
- 마지막에 항상 `other = 반주 − 합`으로 합 보존을 맞추고, 독립 모델을 섞을 때는 stem 간 중복(overlap matrix)을 검사한다.
- 장기적으로 SCNet 계열을 상업 이용 가능한 데이터로 처음부터 학습한다는 방향.

### 2.2 그대로 받아들이면 안 되는 것
이 보고서는 "성능이 좋은 모델"을 중심으로 쓰였고, 이번 계획의 불변 원칙 1(무료 상업 사용 가능만)과 충돌하는 부분이 많다.

| 보고서 후보 | 이번 계획에서의 처리 | 이유 |
|---|---|---|
| SCNet XL IHF, MIMO-SCNet, BS-RoFormer 공개 체크포인트 | **production 제외** | 보고서 스스로 MUSDB18-HQ(학술 전용)로 학습됐다고 밝힘 |
| Banquet / Query-Bandit 공개 체크포인트 | **production 제외** | MoisesDB(CC BY-NC-SA, 비상업)로 학습 |
| HTDemucs 6s | **현재 제외** | 학습 데이터에 MUSDB와 출처 미공개 800곡이 포함. 가중치 라이선스 문장이 없다는 점은 우리 이전 조사에서도 확인 |
| Spleeter 5-stem | **후보(증거 확인 후)** | 보고서는 논문에 코드와 사전학습 모델이 MIT로 배포된다고 서술한다고 함. 우리가 이전에 repo README만 봤을 때는 가중치 문장을 못 찾음 → **정확한 릴리스 파일 기준으로 다시 확인해야 함** |
| "SCNet 계열을 처음부터 직접 학습" | 최종 후보 | 구현 코드와 데이터 라이선스를 각각 확인해야 함(4절) |

- 보고서의 SDR 수치는 데이터셋과 평가 구현이 서로 달라 우리 곡에 그대로 적용할 수 없다. 순위 참고용으로만 본다.
- 보고서의 "Spleeter가 드럼에서 쓸 만할 것"이라는 전제는 **가설**이다. 같은 곡에서 확인하기 전에는 결론이 없다.
- Spleeter 알려진 제약(확인 필요 항목으로 둔다): 기본 모델은 고주파 대역을 잘라서(약 11 kHz) 심벌이 사라질 수 있고, 16 kHz 변형이 있는 것으로 알고 있다. TensorFlow 기반이라 현재 Python/PyTorch 환경과 버전이 충돌할 수 있다. 별도 가상환경이나 별도 프로세스가 필요할 수 있다.
- 보고서의 "상용 사례가 있다"는 서술은 법적 근거가 아니다.
- **전제 한계**: 이번 계획의 불변 원칙을 엄격하게 지키면, 지금 구할 수 있는 사전학습 가중치 중 깨끗한 후보는 Spleeter 정도밖에 없을 가능성이 높다. 이 경우 최종 해결은 직접 학습이 된다.

### 2.3 현재 사용 중인 모델에도 같은 기준을 적용해야 한다
KJ와 Mega53(`core4`, `mega5`, `mega7`, `vocal2`)은 불변 원칙 2를 아직 **완전히 통과하지 못했다**(가중치 허락이 선언 한 건이고 학습 데이터는 미확인). 이 계획은 이 부분을 0단계에서 정식으로 처리한다.

## 4. 평가 설계 (모든 단계에서 공통으로 쓴다)

### 4.1 두 개의 세트
- **Set A — 정답이 있는 세트.** 합법적으로 쓸 수 있는 정답 stem만 사용한다.
  - 우리가 직접 합성한 세트(GeneralUser GS 음색 등 상업 사용이 허용된 음원으로 렌더). 단, 이 세트가 실제곡의 실패를 못 잡았으므로 **마스터링 변형**(압축, 리미팅, 클리핑, EQ, 리버브, 스테레오 확장, MP3/AAC 인코딩, 라우드니스)을 반드시 입힌다.
  - 그 외 공개 데이터셋(예: Slakh2100은 CC BY 4.0)은 **라이선스 검토를 마친 뒤에만** 쓴다. MUSDB18과 MoisesDB는 학술·비상업 제약이 있어 평가에도 쓰지 않는다.
- **Set B — 실제 상용 믹스 세트.** 사용자가 서비스에 올릴 법한 곡. 정답이 없으므로 **블라인드 청취**로 평가한다.
  - 처음 6곡은 유지하되 최종은 18~24곡으로 늘린다. 팝·록·발라드/R&B·어쿠스틱/재즈·EDM·극단 사례(심벌 위주, 작은 드럼)를 포함한다. 지금까지의 6곡은 전부 큰 소리의 팝·록이라 편향되어 있다.

### 4.2 지표
- Set A: SDR, SI-SDR, SIR, SAR + **Drum Recovery Ratio**, **Drum-in-Other Leakage**(드럼이 `other`로 간 비율).
- Set B: 블라인드 청취 점수(stem별 0~100) + 사용자가 지난번 정한 체크 항목(킥·스네어 손실, 심벌 깨짐, 드럼 볼륨 펌핑, 다른 stem 혼입, 서스테인 잘림).
- 두 세트를 섞지 않는다.
- 보조 지표(청취 전 걸러내기): 에너지 이동 분석(`analyze-drum-transfer.py`), 합 보존 오차, NaN/Inf, 클리핑.

### 4.3 합격 기준 (최종 6곡 단계, 24곡 단계에서 확장)
- 드럼: 청취 중앙값 90 이상, 6곡 중 5곡 이상 85 이상, 70 미만인 곡 없음. 정답이 있으면 현재 `core4` 대비 ΔSI-SDR +5 dB 이상 또는 Drum-in-Other Leakage 6 dB 이상 감소.
- 피아노·기타: 중앙값 90 이상, 현재보다 중앙값 +10점 이상. 정답이 있으면 ΔSI-SDR +2 dB 이상, SIR 악화 1 dB 이하.
- 베이스: 현재 점수를 떨어뜨리지 않는다(SI-SDR −0.5 dB 이내). **드럼을 고치다 베이스를 망가뜨리는 후보는 채택하지 않는다.**
- 24곡 최종: stem별 중앙값 90 이상, 하위 10% 80 이상, 60 미만 사례 0개.

### 4.4 블라인드 청취 운영
- 이름과 A/B 순서를 숨기고, stem별로 음량을 맞춘다. 정답표는 평가가 끝날 때까지 열지 않는다. (이전에 만든 `make-listening-package.py`를 재사용한다.)
- 분석은 정규화 전 stem으로 한다. 정규화된 청취 파일은 듣는 용도로만 쓴다.
- 이번 계획에서는 **사용자가 청취를 하고**, 나는 신호 분석과 집계만 한다(지난번 지시 반영).

## 5. 단계별 계획

각 단계는 "시작 조건 / 할 일 / 통과 / 중단 / 라이선스 확인" 순서로 적는다.

### 0단계 — 증거 정리와 평가 준비 (모든 단계의 전제)
- **시작 조건**: 이 계획서 승인.
- **할 일**
  1. 현재 production 모델 5개(KJ, core4, mega5, mega7, vocal2)에 대해 저자에게 **서면 확인을 요청**하는 문안을 만든다(가중치 상업 이용 가능 여부, 학습 데이터 출처). 발송은 사용자 몫이다. 답이 없거나 부정이면 해당 모델은 production 후보에서 내리고 5단계로 앞당긴다.
  2. 후보 모델별 **증거 파일**(가중치 릴리스 URL, SHA256, 라이선스 원문, 학습 데이터 설명)을 `docs/` 아래에 모은다. 근거 없이 `APPROVED`로 바꾸지 않는다.
  3. Set A(마스터링 변형 포함)와 Set B(18~24곡) 구성안을 확정한다. 곡 선정은 사용자와 정한다.
  4. 평가 스크립트를 정리한다: 청취 패키지 생성, 에너지 이동 분석, Drum-in-Other Leakage 계산, 점수 집계.
- **통과**: 증거 파일이 후보별로 갖춰지고, Set A/B 구성과 평가 스크립트가 준비됨.
- **중단**: 해당 없음(준비 단계).
- **라이선스**: 이 단계의 산출물이 곧 라이선스 증거다.

### 1단계 — KJ 입력 경로 확인 (싸고 빠른 점검, 반나절)
드럼이 약한 원인이 `core4` 자체인지, 입력(KJ가 만든 반주)의 특성인지를 가린다. 가중치와 라이선스를 건드리지 않는다.
- **할 일** (같은 최악 곡 1곡 → 6곡)
  1. `core4`에 **원곡 전체**를 직접 넣어 본다(KJ 반주 대신).
  2. `core4` 입력 음량을 6~12 dB 낮춰 본다(클리핑이 많은 마스터 대응).
  3. 위 둘의 결과를 현재 구성과 같은 지표로 비교한다.
- **통과**: 드럼 점수 또는 Drum-in-Other Leakage가 의미 있게 개선(중앙값 +20점 이상 또는 Leakage 6 dB 이상 감소)하면 입력 경로 문제로 확정 → 2단계(KJ 개선)를 우선 진행.
- **중단**: 차이가 거의 없으면 `core4` 자체 문제로 확정 → KJ 입력 경로 연구를 닫고 3단계로 이동. 이 단계에서 더 파고들지 않는다.
- **라이선스**: 추가되는 모델 없음(자체 코드만).

### 2단계 — KJ 개선 (1단계에서 입력 경로가 원인으로 나올 때만 본격 진행, 아니면 보컬 품질 목적의 선택 항목)
KJ 출력(특히 반주)의 품질을 높이는 방법. 전부 **우리가 직접 만드는 추론 코드**이고, 새 가중치를 가져오지 않는다.

| 항목 | 내용 | 비용 | 확인할 것 |
|---|---|---|---|
| 청크·오버랩 조정 | 청크 경계의 잡음 감소 | 오버랩을 늘린 만큼 시간 증가 | KJ에 대해 측정한 적이 없음. 지난 스윕은 `core4`만 대상이었다 |
| TTA | 채널 좌우 바꿔 한 번 더, 위상 반전해 한 번 더, 결과 평균 | 추론 2~3배 | 반주(instrumental)의 보컬 잔향·잔여가 줄어드는지 |
| 반주 정리 | KJ가 남긴 보컬 꼬리를 신호처리로 정리(합 보존) | 새 코드 필요 | 보컬 쪽 손실이 없는지 |
| 앙상블 | KJ 보컬과 `vocal2`(Mega53 보컬 헤드) 보컬을 섞기 | 시간 약 2배 | `vocal2`는 현재 stack과 같은 Mega53 provenance 문제를 공유한다(2.3절). 증거가 해결되기 전에는 참고용 |

- **통과**: 반주 품질(`core4`에 넣었을 때 드럼 점수·Leakage)이 개선되고, 보컬 점수가 떨어지지 않으며, 처리 시간이 허용 범위(사용자와 정한 값)를 넘지 않는다.
- **중단**: 개선이 작거나(드럼 +10점 미만) 비용이 2배를 넘으면 해당 항목은 기각한다.
- **보컬 자체는 현재 90점 이상이라** 이 단계의 목적은 보컬이 아니라 반주 품질이다.

### 3단계 — 깨끗한 후보 모델 비교 (bake-off)
불변 원칙을 통과한 후보만 비교한다. 지금 확인된 후보는 **Spleeter 5-stem 하나**다(2.2절 단서 포함).
- **시작 조건**: 0단계에서 후보의 가중치 라이선스 증거가 확인됨.
- **할 일**
  1. 환경 호환성 확인(TensorFlow 의존성). 안 맞으면 **별도 가상환경 + 별도 프로세스**로 호출하는 어댑터를 만든다(본체 환경을 오염시키지 않는다).
  2. 고주파 대역 제한 확인(11 kHz 대 16 kHz 변형). 심벌이 필요한 드럼에서 중요하다.
  3. **1곡**: `core4` 대 Spleeter의 drums(그리고 piano, bass)를 블라인드로 비교한다.
  4. 통과하면 **6곡**으로 확대한다.
- **통과**: 드럼이 80점 이상이고(4.3절의 6곡 기준 충족), 베이스 점수가 떨어지지 않으면 4단계로.
- **중단**: 드럼이 80점에 못 미치면 Spleeter 단독으로는 부족한 것이다 → 5단계(직접 학습)로 이동한다. 이 단계의 결과가 나쁘다고 DSP 보정(B안)으로 우회하지 않는다.
- **라이선스**: 후보마다 증거 파일 필수. 증거가 나오지 않으면 비교 대상에서 제외한다.

### 4단계 — stem별 라우터와 중간 릴리스 (3단계에서 통과한 모델이 있을 때)
- **할 일**
  1. `commercial_6`을 stem별로 모델을 갈아 끼울 수 있는 구조로 바꾼다. 예: `drums: spleeter5`, `piano/guitar/bass: core4`, `other: 합 보존 잔차`.
  2. 합 보존과 stem 간 중복(overlap matrix) 검사를 넣는다. 독립 모델 둘이 같은 성분을 모두 가져가면 합이 두꺼워지거나 `other`가 음수 성분을 갖는다.
  3. 레지스트리·승인 파일·릴리스 allowlist·`/licenses`를 같은 변경에서 함께 갱신한다. 새 모델은 증거 파일이 확정된 뒤에만 `APPROVED`로 올린다.
  4. 회귀 테스트(6개 stem 계약, 합 보존, NaN/Inf, 클리핑)와 서비스 E2E를 다시 통과시킨다.
- **통과**: 6곡 합격 기준 충족 + 기존 테스트 통과.
- **중단**: 라우터 결합으로 합 보존이나 stem 간 중복이 깨지면 병합하지 않는다.

### 5단계 — 깨끗한 데이터로 직접 학습 (3단계가 부족하거나 0단계에서 현재 모델이 탈락할 때)
가장 비싸고 가장 오래 걸리는 단계다. 시작 전에 사용자 승인과 별도의 세부 계획서가 필요하다.
- **구조 후보**: SCNet 계열(소형부터). 이미 vendoring된 BS-RoFormer/MelBand-RoFormer 구현도 대안이다. 구현체 라이선스는 정확한 파일 기준으로 먼저 확인한다.
- **데이터 후보와 확인할 점**
  - 합성 데이터(Slakh2100 등 CC BY 계열): 렌더링에 쓰인 가상악기 라이브러리의 학습 사용 권리를 **확인하지 못했다.** 이전에 검토한 StemGMD(Apple 샘플 라이브러리 기반)와 같은 종류의 쟁점이다.
  - 자체 합성: 상업 사용이 허용된 음원(SoundFont 등)과 권리가 확인된 MIDI로 직접 렌더링한다. 가장 안전하지만 실제 녹음과의 격차가 크다.
  - 권리를 보유한 실제 멀티트랙: 확보 방법을 사용자와 정해야 한다(직접 녹음, 계약 등). 공개 무료 데이터셋 중 상업 학습이 허용된 실제 멀티트랙은 지금 확인된 것이 없다.
  - **MUSDB18, MoisesDB는 학습에도, 검증에도 쓰지 않는다.**
- **필수 학습 조건**: 마스터링 변형(압축·리미팅·클리핑·EQ·리버브·스테레오 확장·코덱·라우드니스)을 학습 데이터에 넣는다. 합성 평가에서 −2.2 dB, 실제곡에서 −11 ~ −28 dB가 나온 도메인 격차 때문이다.
- **금지**: 비상업 사전학습 가중치의 미세조정. 무작위 초기화 또는 상업 사용이 확실한 초기화만 허용한다.
- **자원**: RTX 3060 12GB 기준 소형 모델로 수 일~수 주로 **추정**한다(측정 전에는 신뢰하지 말 것). 시작 전 1시간 시험 학습으로 실제 속도와 메모리를 측정하고 일정을 다시 잡는다.
- **통과 기준**: 4.3절과 같다. 24곡 합격 기준을 충족해야 production 후보가 된다.
- **중단**: 데이터 권리 확인이 안 되면 시작하지 않는다. 시험 학습의 속도가 일정을 감당할 수 없으면 범위를 줄이거나 중단한다.

### 6단계 — 13트랙과의 연결 (후속)
`commercial_13`도 같은 `core4` 위에 있어서 6트랙 결과가 13트랙에도 영향을 준다. 6트랙 라우터가 확정되면 13트랙의 같은 단계도 같은 방식으로 교체하고 13/13 계약과 합 보존을 다시 검증한다. 질의 기반 분리(Banquet식)와 보컬 역할 분리는 이번 계획 범위 밖이다.

## 6. 변경 범위 (4단계 이후에 코드를 건드릴 때)
- `separation/src/music_analyzer/commercial_pipeline.py`: stem별 백엔드 설정, 새 stage preset.
- `registry.py` / `commercial_approval.json` / `separation/configs/models/*.json`: 새 모델 등록, 증거 URL과 SHA256.
- `release_presets.json`: 새 구성을 `VALIDATING`으로 올린 뒤 승인 절차를 거친다.
- 새 어댑터(필요 시 별도 프로세스): 외부 모델 호출 격리.

- 문서: `/licenses`와 `PRODUCTION_DEPENDENCY_MANIFEST.json`을 같은 변경에서 재생성하고 `--check`를 통과시킨다.

## 7. 위험과 미해결 사항
| 위험 | 영향 | 대응 |
|---|---|---|
| 깨끗한 사전학습 후보가 Spleeter 하나뿐일 가능성 | 3단계 이후 직접 학습으로 넘어감 | 0단계에서 후보를 최대한 확정하고, 직접 학습은 별도 승인을 받는다 |
| Spleeter 가중치 라이선스가 릴리스 파일 기준으로 확인되지 않음 | 후보 탈락 | 확인 안 되면 즉시 제외 |
| 현재 KJ/Mega53의 근거가 저자 서면으로 확정되지 않음 | 지금 서비스 중인 구성이 불변 원칙을 완전히 충족하지 못함 | 0단계 문의. 거절되면 5단계를 앞당긴다 |
| 평가 정답 부족(실제곡은 정답이 없다) | 객관 지표로 결론을 못 냄 | 마스터링 변형을 입힌 합성 세트 + 블라인드 청취를 병행 |
| 청취 평가가 사용자 시간에 의존 | 일정 지연 | 1곡 → 6곡 → 24곡으로 단계 축소, 중단 기준 적용 |
| TensorFlow 의존성이 현재 환경과 충돌 | 통합 비용 증가 | 별도 환경·프로세스 격리 |
| 직접 학습의 데이터 권리와 시간 | 일정 불확실 | 시작 전 별도 계획서와 시험 학습 측정 |

## 9. 결정이 필요한 것
1. **비상업 가중치를 "측정용 자"로만 쓰는 것을 허용할지.** 엄격하게 지키면 SCNet·HTDemucs·Banquet 공개 체크포인트는 production은 물론 측정에도 쓰지 않는다. 이 경우 3단계 비교 대상이 Spleeter 하나로 줄어든다. 허용하면(오프라인 측정 한정, 서비스에 포함하지 않음) 모델 세대 교체의 효과를 먼저 알 수 있다. **기본값은 허용하지 않음**으로 적어 두었다.
2. 청취 시험용 곡을 몇 곡, 어떤 장르로 할지(4.1절).
3. 처리 시간 한도(예: 3분 곡 기준 몇 분까지). 2단계 TTA·앙상블의 합격 기준에 필요하다.
4. 5단계(직접 학습)에 진입할 때 쓸 수 있는 데이터(직접 녹음 가능 여부 등).
5. 0단계의 저자 문의 발송 여부와 담당.
