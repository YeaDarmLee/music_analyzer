# 분석 버전 선택

새 분석 → 2·6·11트랙 선택 → 다음 → 파일 업로드 → 분석 시작 순서로 실행한다. 버전을 선택하기 전에는 업로드 단계로 이동할 수 없다. 업로드 전에는 버전 선택 탭으로 돌아갈 수 있다.

| 구성 | 출력 | 실행 |
|---|---|---|
| 2트랙 (`basic_2`) | 보컬, 전체 반주 | 보컬·반주 모델만 실행 |
| 6트랙 (`basic_6`) | 보컬, 피아노, 기타, 베이스, 드럼, 나머지 | 보컬·반주와 6-source 악기 모델 실행 |
| 11트랙 (`final_11`) | 보컬, 코러스, 피아노, 신디, 스트링, 브라스, 통기타, 일렉기타, 베이스, 드럼, 나머지 | 보컬·코러스 → 악기 8개 → 나머지1 → 신디·스트링·브라스 보완 → 나머지2 |

2·6트랙의 보컬은 메인보컬과 코러스를 함께 유지한다. 6트랙 기타는 기존 악기 모델의 기타 출력이며, 11트랙의 두 기타를 합치는 경로가 아니다. 6트랙의 나머지는 분리된 반주에서 피아노·기타·베이스·드럼을 뺀 신호다.

보완 추론은 해당 악기를 나머지에서 추출해 해당 트랙에 더하고 나머지에서 뺀다. 스트링과 브라스는 신디 추출 조건을 재사용하지 않는다. 텍스트 제외 조건이 다른 악기의 완전 차단을 보장하지는 않는다. 새 11트랙 경로에서는 추가 브라스·스트링 음량 억제를 실행하지 않는다. 기존 `final_10` 경로는 유지한다.

11트랙은 보컬·반주 분리 직후 보컬·코러스를 분리한다. 반주에서 기본 악기 8개를 빼 나머지1을 만들고, 신디 → 스트링 → 브라스 순서로 현재 나머지에서 보완한다. 각 보완분은 해당 악기에 더한다. 최종 나머지2는 반주에서 보완된 최종 악기 8개를 빼 계산하므로 나머지1에서 세 보완분을 뺀 것과 같다. 최종 화면과 다운로드에는 나머지2만 제공한다.

2트랙은 원곡 합계를, 6·11트랙의 악기와 나머지는 분리된 반주 합계를 검증한다. 6·11트랙 전체 합계가 원곡과 정확히 같다고 보장하지 않는다. 기존 완료 결과 및 기존 `final_10` 호출은 기존 경로를 유지한다. 기존 무음 트랙 숨김 정책 때문에 실제 화면·ZIP의 트랙 수는 무음 출력이 있으면 줄어들 수 있다.

검증: 관련 Python 테스트와 프런트 빌드, 버전 선택 → 파일 업로드의 브라우저 전환. 실제 GPU 10초 음원 검증은 `scripts/smoke-analysis-versions.py <44.1kHz 스테레오 WAV>`로 실행하며 `data/part-studies/analysis-versions-smoke/verification.json`에 기록한다. 짧은 실행 검증은 브라스 보완의 청취 품질이나 전체 곡 처리시간을 보장하지 않는다.

## 11트랙 단계별 분리 v8

2·6트랙은 유지한다. 11트랙은 보컬·코러스 분리 후 반주에서 피아노·기타·베이스·드럼을 추출해 나머지1을 만든다. 기타 입력으로 Mega5를 실행해 어쿠스틱·일렉기타 출력만 사용하고 두 출력을 뺀 기타 잔여는 독립 트랙으로 제공한다. 나머지1 입력으로 Mega5를 실행해 신디·스트링·브라스 출력만 사용한다. 나머지2에서 신디 → 스트링 → 브라스를 순서대로 보완하며 매번 해당 보완분을 악기에 더하고 현재 나머지에서 뺀다. 최종 출력은 나머지3을 포함한 11트랙과 기타 잔여, 총 12개다. 기타 잔여는 보완 추론 입력에 섞지 않으며 반주 합계 검증에는 포함한다. 이전 문서의 v7 설명은 기존 결과에 해당한다.
